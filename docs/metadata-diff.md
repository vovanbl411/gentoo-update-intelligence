# Первый срез Gentoo metadata diff

Документ описывает Go-контракт, но не задаёт JSON API или схему хранения. Он фиксирует реализованное поведение сравнения двух подготовленных снимков `metadata/md5-cache`. Компонент не получает и не проверяет источник: снимки и их происхождение передаёт вызывающий код.

## Границы

Сравниваются только `EAPI`, `SLOT` / `SUBSLOT` и `IUSE` для одного `category/name` и одного имени репозитория. Версии и commits могут различаться; версию компонент не сортирует, направление задаёт порядок аргументов `Compare`. Имя репозитория хранится отдельно от URL зеркала.

Компонент реализован в `backend/internal/metadatadiff` и использует только стандартную библиотеку Go. Он не выполняет I/O, сетевые запросы, ebuild, обращения к БД или Redis, не генерирует постоянные ID или время и не изменяет аргументы. Вызовы с одинаковыми аргументами дают одинаковый результат. Поля вне трёх выбранных групп игнорируются.

Семантика нормализации опирается на [Package Manager Specification для EAPI 8](https://projects.gentoo.org/pms/8/pms.pdf) и [руководство Gentoo по SLOT](https://devmanual.gentoo.org/eclass-reference/ebuild/). В частности, SLOT и SUBSLOT используют slot-name grammar PMS; имя USE-флага начинается с ASCII-буквы или цифры и далее содержит символы из `[A-Za-z0-9+@_-]`. В EAPI 8 IUSE defaults поддерживаются; один начальный `+` или `-` задаёт default, а не эффективное состояние пользовательской конфигурации.

## Go API

Публичные точки входа:

```go
func Normalize(source Source, content string) Snapshot
func Compare(before, after Snapshot) Result
```

`Source` содержит обязательные непустые `Category`, `Name`, `Version`, `Repository`, `SourceURL`, `Commit` и `CachePath`. Проверка не выводит происхождение из локального имени файла и не трактует URL зеркала как имя репозитория. Если любое поле пусто хотя бы у одной стороны, сравнение `unavailable`.

`Snapshot` хранит исходный `Source`, `Content` без изменений и lowercase hex SHA-256 точных байтов `Content`, а также `EAPI`, `Slot`, `IUSE` и `Diagnostics`. Хеш не вычисляется по нормализованному содержимому, Git blob SHA или `_md5_`.

У `EAPI`, `Slot` и `IUSE` есть `State`: `valid`, `missing` или `invalid`. Только `valid` обозначает известное значение. Для IUSE допустим `valid` с пустым набором. Для отсутствующих и некорректных полей нулевые Go-значения не считаются известными данными.

### Чтение cache

Строка делится по первому `=`; строки нумеруются с 1. Исходное содержимое, порядок строк, табуляция и остальные байты сохраняются. Выбираются только точные ключи `EAPI`, `SLOT` и `IUSE`. Повтор ключа с тем же значением принимается и сохраняет evidence всех строк. Разные значения повторного ключа делают всё поле `invalid`.

### EAPI

Для нормализации поддерживается только буквальное значение `8`. Корректное имя другого EAPI сохраняется с состоянием `valid`, `Supported=false` и диагностикой `EAPI_UNSUPPORTED`. Пустое или синтаксически некорректное значение — `invalid`; отсутствующий ключ — `missing`. Сравнение не трактует отсутствующий EAPI как EAPI 0: принятый контракт требует явный EAPI 8 в обеих cache-записях. При missing, invalid или unsupported EAPI `Normalize` не считает SLOT и IUSE достоверными по правилам EAPI 8. `Compare` возвращает `unavailable`, пустые `ComparedFields` и семантические `Changes`.

### SLOT / SUBSLOT

Для EAPI 8 корректная запись сохраняет исходный `Raw`, нормализованные `Name` и `Subslot`, `ExplicitSubslot` и номера строк. Значение без `/` даёт SUBSLOT, равный SLOT; значение с одним `/` задаёт явный SUBSLOT. Поэтому `2` и `2/2` равны при сравнении. Пустые части, более одного `/`, пробелы и значения вне slot-name grammar делают всю группу `SLOT` / `SUBSLOT` недоступной.

Изменения нормализованных SLOT и SUBSLOT представлены отдельно. Различие только в явности SUBSLOT сохраняется в snapshot, но не создаёт изменение.

### IUSE

Токены разделяются пробельными символами. Начальные `+` и `-` означают соответственно `enabled` и `disabled`; без префикса default — `unspecified`. Например, `foo`, `+foo` и `-foo` являются разными объявлениями одного флага. Имена проверяются по PMS EAPI 8. Маркеры `*` / `%` вывода `emerge` не являются частью этого формата.

Порядок токенов не влияет на сравнение. Повторные одинаковые объявления допустимы и сохраняют каждую исходную строку и токен. Повторные ключи IUSE допустимы только при совпадающем исходном значении. Противоречивые defaults одного имени или любой некорректный токен делают весь IUSE `invalid`; оставшиеся имена не сравниваются как полный набор. `IUSE=` — корректный пустой набор, отсутствие ключа — `missing`.

Сравнение выдаёт отсортированные по имени списки `Added`, `Removed` и `DefaultChanges`. Added/removed содержат объявленный default флага. Default changes формируются только для имён, присутствующих с обеих сторон. Удалённый флаг не создаёт дополнительного изменения default.

## Результат сравнения

`Result` содержит типизированный `Status` (`available`, `partial` или `unavailable`), `ComparedFields`, типизированные `Changes`, `Limitations` и `Before` / `After` — ссылки на `Source` и SHA-256 обеих сторон.

Порядок групп фиксирован: `EAPI`, `SLOT`, `IUSE`. Если оба EAPI поддерживаются, `EAPI` входит в `ComparedFields`, даже если различий нет. Корректные SLOT и IUSE сравниваются независимо: повреждение обеих групп даёт `partial` только с `EAPI`; повреждение одной группы оставляет вторую сравнимой. `available` означает, что сравнены все три группы, `partial` — только часть, `unavailable` — сравнение не началось из-за происхождения, идентичности или EAPI.

Сначала проверяются обязательные поля источника, затем совпадение `category/name` и имени репозитория, затем наличие EAPI 8 с обеих сторон. Разные версии и commits допустимы. При невозможности сравнения `ComparedFields` и семантические `Changes` пусты. Пустые `Changes` означают отсутствие различий только в перечисленных `ComparedFields`; недоступные данные не считаются удалением.

Evidence — типизированная ссылка с `Side` (`before` / `after`), `Field` и номерами исходных строк. Для отсутствующего ключа `WholeSnapshot=true` и номера строк не задаются; такая ссылка также включена в соответствующее `Limitation`. Для SLOT обе нормализованные части ссылаются на строки ключа `SLOT`; IUSE-изменения ссылаются на строки объявления флага, а для добавленного или удалённого флага — также на полный список IUSE противоположной стороны. Постоянных ID нет.

### Диагностики и порядок

`Snapshot.Diagnostics` выдаются группами в порядке `EAPI`, `SLOT`, `IUSE`; внутри группы сохраняется порядок исходных строк и токенов. Реализованы коды:

| Поле | Код | Причина |
|---|---|---|
| EAPI | `EAPI_MISSING` | Ключ отсутствует. |
| EAPI | `EAPI_INVALID` | Значение пусто или имя EAPI нарушает синтаксис PMS. |
| EAPI | `EAPI_CONFLICTING_VALUES` | Повторные ключи содержат разные значения. |
| EAPI | `EAPI_UNSUPPORTED` | Значение корректно, но не равно `8`. |
| SLOT | `SLOT_MISSING` | Ключ отсутствует. |
| SLOT | `SLOT_INVALID` | Значение нарушает синтаксис SLOT/SUBSLOT. |
| SLOT | `SLOT_CONFLICTING_VALUES` | Повторные ключи содержат разные значения. |
| SLOT | `SLOT_EAPI_UNAVAILABLE` | SLOT нельзя интерпретировать, потому что EAPI отсутствует, повреждён или не поддерживается. |
| IUSE | `IUSE_MISSING` | Ключ отсутствует. |
| IUSE | `IUSE_CONFLICTING_VALUES` | Повторные ключи содержат разные значения. |
| IUSE | `IUSE_INVALID_TOKEN` | Токен содержит некорректное имя флага. |
| IUSE | `IUSE_CONFLICTING_DEFAULTS` | Имя флага объявлено с разными defaults. |
| IUSE | `IUSE_EAPI_UNAVAILABLE` | IUSE нельзя интерпретировать, потому что EAPI отсутствует, повреждён или не поддерживается. |

`Result.Limitations` упорядочен так: отсутствующие поля источника (сначала before, затем after; внутри фиксированный порядок полей), несовпадение пакета, несовпадение репозитория, недоступность EAPI (before, after), SLOT (before, after), IUSE (before, after). Диагностики остаются на снимках и не дублируются в результате.

## Интерпретационные ограничения и вне scope

Сравнение состояний выбранного репозитория не подтверждает, что эти metadata использовались при сборке установленного пакета пользователя. Удаление флага из IUSE не показывает, был ли он включён в пользовательской конфигурации. Изменение SUBSLOT само по себе не определяет список пакетов для пересборки.

Этот срез не сравнивает зависимости, `REQUIRED_USE`, `LICENSE`, `SRC_URI`, ebuild или Gentoo patches. Он не вычисляет effective configuration, upstream notes или findings, не реализует approval, Metadata Provider, синхронизацию и полный `ChangeReport`, не подключён к Analyzer. Статус `not_applicable` не используется.

## Реальные fixtures и проверки

Тесты читают неизменённые cache-файлы и используют происхождение из [provenance.md](../testdata/metadata/provenance.md). Для `dev-libs/libxml2` версии `2.13.9` и `2.14.6` относятся к одному commit репозитория `gentoo` на зеркале `gentoo-mirror/gentoo`. Fixture проверяет заданные SHA-256, EAPI 8, переход SUBSLOT `2` → `16`, удаление `examples` и `lzma`, отсутствие остальных изменений и корректные номера строк evidence. Ожидаемое описание остаётся в [libxml2.expected.md](../testdata/metadata/libxml2.expected.md).

Синтетические сценарии помечены в тестах `synthetic/`. Они покрывают отсутствие изменений, порядок IUSE, добавление и удаление, переходы defaults, равенство `2` и `2/2`, пустое и отсутствующее IUSE, некорректные и повторные ключи, SLOT/EAPI ошибки, partial/unavailable, идентичность, обязательное происхождение, разные commits, неизменность входов и детерминированность результата.

Проверки реализации (из каталога `backend/`): `gofmt` для изменённых Go-файлов, `go test ./...`, `go vet ./...` и `git diff --check`.
