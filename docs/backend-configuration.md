# Конфигурация backend

Backend загружает настройки один раз при запуске: **defaults → явно указанный YAML → непустые переменные окружения**. Основной источник требований — [спецификация backend-configuration](../openspec/specs/backend-configuration/spec.md). API v1 и формат сохранённых результатов от выбора источника настроек не меняются.

## Файл и запуск

В штатном Compose используется [config/backend.yaml](../config/backend.yaml). Файл подключён только для чтения как `/etc/gentoo-update-intelligence/backend.yaml`; backend получает путь аргументом `--config`. Файл на хосте должен существовать: Compose не создаёт каталог вместо отсутствующего файла.

После первого обновления backend обычные настройки меняются без пересборки образа. Измените нужное поле YAML и выполните из корня проекта:

```sh
docker compose restart backend
```

Команды Compose автоматически читают действующий `POSTGRES_PASSWORD` из `.env` в корне проекта. При перезапуске незавершённые задания восстанавливаются по контракту очереди; завершённые результаты остаются в PostgreSQL.

Другой файл на хосте выбирается через `BACKEND_CONFIG_PATH`:

```sh
export BACKEND_CONFIG_PATH='./config/backend.custom.yaml'
```

Затем пересоздайте backend, чтобы изменить источник bind mount:

```sh
docker compose up -d --no-deps backend
```

При запуске бинарника вне Compose передайте `--config /path/to/backend.yaml`. Без этого аргумента никакие файлы автоматически не ищутся: используются defaults и env. Если аргумент указан, отсутствие или ошибка файла останавливает запуск, даже когда env достаточно для запуска без файла. Includes и подстановка `${VARIABLE}` внутри YAML не выполняются.

## Поля YAML

Значения в колонке defaults относятся к запуску без файла. Штатный файл Compose отличается адресом HTTP, включёнными overlays и worker; отличия указаны в таблице.

| Поле | Defaults / штатный Compose | Смысл |
|---|---|---|
| `startup_timeout` | `15s` | Общее время начального подключения к БД, миграций и возврата прерванных заданий в очередь. |
| `http.listen_address` | `127.0.0.1:8080` / `0.0.0.0:8080` | Адрес внутри процесса или контейнера; публикация порта на хост задаётся в Compose. |
| `http.read_header_timeout` | `5s` | Ожидание HTTP-заголовков запроса. |
| `http.idle_timeout` | `60s` | Ожидание следующего запроса в неактивном HTTP-соединении. |
| `analysis.concurrency_limit` | `1` | Предел активных анализов; `0` отключает предел. |
| `repository.name` | `gentoo` | Имя основного repository. При включённых overlays требуется gentoo. |
| `repository.source_url` | `https://anongit.gentoo.org/git/repo/gentoo.git` | Заявленное происхождение для backend и provenance; само по себе не перенастраивает sync. |
| `repository.path` | `/metadata/gentoo.git` | Локальный путь к mirror. |
| `repository.commit` | `""` | Необязательный полный SHA-1/SHA-256 commit; пустая строка выбирает опубликованную ревизию при начале нового анализа. |
| `overlays.path` | `""` / `/overlays` | Каталог зеркал overlays; пустая строка отключает их подготовку. |
| `overlays.catalog` | `[]` | Дополнительные доверенные записи `name`, `url`, `masters`; встроенный guru остаётся. |
| `metadata.worker_url` | `""` / `http://metadata-worker:8090` | Адрес worker; пустая строка отключает обращения к нему. |
| `metadata.profile` | `profiles/default/linux/amd64/23.0` | Профиль Portage. Пустая строка выбирает default; для overlay backend добавляет master gentoo, если префикс не указан. |
| `metadata.worker_timeout` | `20m` | Ожидание одного HTTP-запроса к worker. Это не общий срок анализа и не гарантия остановки генерации. |

Все четыре таймаута требуют положительной длительности с единицами, например `5s`, `100ms` или `20m`. `0`, `0s`, отрицательные значения и переполнение недопустимы. Лимит анализов требует неотрицательного целого; дробные числа не принимаются.

Частичный YAML сохраняет defaults пропущенных полей. Пустые строки и списки записываются явно: `""` и `[]`; YAML null не принимается. Пустой документ, неизвестные/повторные ключи, неверные типы и несколько YAML-документов останавливают запуск. Проверка не требует готового Gentoo mirror и не проверяет доступность сети: первая синхронизация может продолжаться после запуска backend.

Пути внутри YAML разрешаются относительно рабочей директории процесса. В Compose используйте пути внутри контейнера и согласуйте их с подключёнными volumes. Изменение строки пути не создаёт mount. Если меняете источник Gentoo, согласуйте `repository.source_url` с URL sync-сервиса; backend не управляет его конфигурацией.

## Переменные окружения и секреты

Все имена в следующей таблице имеют префикс `GENTOO_UPDATE_INTELLIGENCE_`. Непустое значение перекрывает YAML, пустое игнорируется. Строка `0` непустая и отключает предел анализов. Отключать необязательные функции пустой строкой следует в YAML.

| Суффикс env | Поле |
|---|---|
| `LISTEN_ADDR` | `http.listen_address` |
| `ANALYSIS_CONCURRENCY_LIMIT` | `analysis.concurrency_limit` |
| `REPOSITORY` | `repository.name` |
| `SOURCE_URL` | `repository.source_url` |
| `REPOSITORY_PATH` | `repository.path` |
| `COMMIT` | `repository.commit` |
| `OVERLAY_PATH` | `overlays.path` |
| `OVERLAY_CATALOG` | `overlays.catalog`, в виде прежнего JSON-массива |
| `METADATA_WORKER_URL` | `metadata.worker_url` |
| `METADATA_PROFILE` | `metadata.profile` |
| `STARTUP_TIMEOUT` | `startup_timeout` |
| `HTTP_READ_HEADER_TIMEOUT` | `http.read_header_timeout` |
| `HTTP_IDLE_TIMEOUT` | `http.idle_timeout` |
| `METADATA_WORKER_TIMEOUT` | `metadata.worker_timeout` |

Env-каталог заменяет YAML-список дополнений целиком, а не добавляется к нему. Встроенный guru сохраняется; повторное имя остаётся неоднозначным по прежним правилам. Разрешены доверенные HTTPS URL без credentials, query и fragment либо абсолютные локальные пути; URL из плана не используются. Неизвестный master мешает запуску. Профиль, настройка выбора commit, пути и каталог фиксируются для текущего запуска backend; env не читается заново во время анализа.

`GENTOO_UPDATE_INTELLIGENCE_DATABASE_URL` обязателен и задаётся только через env. Поля для DSN и пароля в YAML нет. Compose формирует DSN из действующего `POSTGRES_PASSWORD`; пароль не нужно переносить в tracked-файл. Полный YAML и эффективная конфигурация не выводятся в журнал. Ошибки разбора показывают источник и позицию либо поле, без исходных значений; ошибки подключения к PostgreSQL не выводят DSN.

Для совместимости Compose выбирает происхождение Gentoo в таком порядке: непустой `GENTOO_UPDATE_INTELLIGENCE_SOURCE_URL`, затем непустой общий `GENTOO_REPOSITORY_URL`, затем YAML/default. Общая переменная по-прежнему настраивает и sync. Если заданы обе, оператор должен убедиться, что происхождение backend соответствует фактическому источнику mirror.

При изменении env нужно пересоздать контейнер; `restart` сохраняет прежнее окружение. Даже после редактирования YAML непустой override из существующего контейнера продолжит иметь приоритет. Чтобы убрать его, очистите переменную для Compose и пересоздайте backend.

## Первое применение

При уже запущенных зависимостях:

```sh
docker compose up -d --no-deps --build backend
```

Команда предполагает, что зависимости уже работают. Для полного запуска остановленного стека используйте `docker compose up -d`. Это первое обновление бинарника и подключение YAML. Последующие изменения того же файла применяются через restart без `--build`; изменение env или `BACKEND_CONFIG_PATH` требует recreate. Миграция БД не нужна. Для конфигурации не требуется пересборка frontend или Gentoo runtime; если предыдущий переход на API v1 ещё не применялся, backend и frontend обновляются вместе по [инструкции API](http-api.md#применение-и-конфигурация).

Лимит генераций, cache и временный каталог относятся к worker; период синхронизации — к sync-сервису. Сети, capabilities и volumes остаются в Compose. Версия API и правила анализа через этот файл не меняются.
