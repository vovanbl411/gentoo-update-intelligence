# Proposal

## Why

В репозитории пока нет воспроизводимого локального запуска frontend, backend и PostgreSQL как единого сервиса; компоненты можно проверить по отдельности. Compose позволит пройти путь от отправки плана в браузере до повторного чтения анализа после пересоздания контейнеров.

## What Changes

- Добавить локальную Compose-конфигурацию для frontend, backend и PostgreSQL; публиковать на хосте только frontend и только на loopback.
- Отдавать собранный frontend, поддержать прямое открытие `/analyses/<uuid>` и проксировать `/api` в backend со снятием префикса, сохраняя статус, тип содержимого и тело ответов API.
- Сохранять анализы в именованном томе PostgreSQL. Явно передавать backend путь к подготовленному Git-снимку и полный commit, подключая снимок только для чтения.
- Документировать предварительную подготовку снимка, необходимые параметры запуска и приёмочный сценарий с реальным планом, двумя Lookup для `dev-libs/libei`, сверкой UUID и результата API после пересоздания контейнеров.
- Оставить без изменений HTTP-контракт и логику анализа. Redis, генерация metadata, аутентификация и публичное развёртывание не входят в change.

## Capabilities

### New Capabilities
- `local-compose`: локальный запуск сервиса, доступ к его компонентам, маршрутизация frontend, закреплённый read-only metadata snapshot и сохранение данных PostgreSQL между пересозданиями контейнеров.

### Modified Capabilities

Нет. Существующие требования frontend и HTTP API сохраняются без изменений.

## Impact

- Новые Compose-файл и конфигурация сборки/runtime для frontend и backend.
- Документация локального запуска и подготовки metadata snapshot.
- Docker Compose как инструмент локального запуска; HTTP API, схема анализа и формат ответа не меняются.
