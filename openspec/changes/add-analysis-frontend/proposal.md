## Why

Backend умеет сохранять анализ emerge-плана и возвращать его по UUID, но пользователь
пока не может пройти этот путь в браузере. Первый frontend должен позволить отправить
план, проверить выводы и повторно открыть тот же сохранённый результат по ссылке.

## What Changes

- Форма для emerge-плана и необязательного списка локально патченных `category/name`.
- Отправка в существующий `POST /analyses` и переход на `/analyses/<uuid>` после успеха.
- Просмотр статуса и диагностик Parser, изменений пакетов, findings с основаниями,
  доступного metadata diff и причин недоступности, возвращённых API.
- Загрузка сохранённого анализа через `GET /analyses/{id}` при прямом открытии и refresh.
- Отдельные состояния отправки, загрузки, ошибки запроса, недоступного сервиса и 404;
  сохранение ввода в форме при неуспешной отправке.

## Capabilities

### New Capabilities

- `analysis-frontend`: браузерный путь от ввода плана до просмотра сохранённого анализа.

### Modified Capabilities

Нет. Контракты backend из `docs/http-api.md`, Parser, Analyzer и ChangeReport не меняются
и остаются основными источниками требований своих областей. Новая спецификация
описывает только поведение браузерного интерфейса; существующие области не переносятся.

## Impact

Планируется отдельный `frontend/`, его тесты и инструкция локального запуска.
Для разведения browser routes и API нужен локальный proxy; Docker Compose,
публичное развёртывание и аутентификация не входят в change.

Не входят: обновление системы, клиентский Gentoo-анализ, пользовательские отметки,
ручная переклассификация, новые правила Analyzer, Redis и генерация metadata по HTTP.

## Acceptance

- Реальный план проходит через настоящий API; UI соответствует полям его ответа.
- Для `dev-libs/libei` закреплён один cache-снимок с версиями `1.6.0` и `1.6.0-r1`; оба Lookup возвращают `found`, доступное сравнение отображается и сохраняется при повторном открытии. Отсутствие различий в поддерживаемых полях не подменяется недоступностью metadata.
- Новая вкладка по выданной ссылке и refresh показывают тот же сохранённый анализ.
- Отдельно проверены partial, unsupported, неизвестный UUID, недоступность сервиса
  и сбой сохранения с сохранением введённого текста.
- Автоматические проверки используют контролируемые ответы API; реальный сквозной
  прогон отдельно подтверждает работу с backend и PostgreSQL. Невыполненный прогон
  указывается как ограничение, а не заменяется mock-проверкой.
