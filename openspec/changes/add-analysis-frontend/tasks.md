### Подготовка metadata для задачи 4.3

- Использовать локальный Git-снимок с точными файлами `metadata/md5-cache/dev-libs/libei-1.6.0` и `metadata/md5-cache/dev-libs/libei-1.6.0-r1` в одном закреплённом commit. Backend настроить на этот commit и логическое имя repository `gentoo`.
- Исходная точка — описанный в `docs/metadata-preparation.md` снимок `1d1580515aeae5bf0c3d33a9d7d099bdc4a2aed3`. Перед использованием проверить наличие Git-объектов и содержимое файлов; наличие прежних временных артефактов не предполагается. Ожидаемые SHA-256: `1.6.0` — `0168526a96c712e1fad72f920ba5fbf3af34ddbcca1fd69db5c211448ffa0002`, `1.6.0-r1` — `e0d82b81a0e872e19cefc32a1f0229a23628726acf8a2ecd2ad53e965f4337e8`.
- Если снимок утрачен, подготовить обе версии по контракту `docs/metadata-preparation.md`, сохранив provenance и SHA-256, и закрепить cache отдельным Git-снимком. Создание такого снимка требует явного разрешения на `git commit`; при отсутствии разрешения или окружения отметить 4.3 незавершённой. Не подменять реальные cache синтетическими и не выполнять fetch без соответствующего разрешения.
- До браузерного прогона подтвердить через существующий Provider/CLI оба Lookup `found`, соответствие версий и SHA-256. Source commits ebuild не подставлять вместо commit cache-снимка.
- Для документированной пары поддерживаемый diff EAPI, SLOT/SUBSLOT и IUSE пуст. Проверить наличие сравнения и `ComparedFields`, затем отображение отсутствия различий в сравнённых полях при первом просмотре, в новой вкладке и после refresh. Не требовать изменений DEPEND/RDEPEND и не расширять diff engine в этом change. Непустой diff проверяется в задаче 3.4 на контролируемом fixture.
- Пустой снимок или `not_found` для любой версии не закрывает 4.3: такой прогон проверяет только недоступность metadata. В отчёте отделить подготовку окружения, выполненный реальный прогон и невыполненные проверки.
