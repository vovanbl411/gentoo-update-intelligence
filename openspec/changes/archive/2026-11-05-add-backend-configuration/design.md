# Design

## Context

Backend читает env при старте и подготовке каждого анализа. Мотивация описана в proposal.md. Прежние изменения API v1 и очереди сохраняются.

## Decisions

- Пакет backendconfig содержит типы, defaults, строгий загрузчик и проверку. Используется go.yaml.in/yaml/v3 v3.0.6. Другие компоненты получают готовые значения, а не читают env.
- Без --config используются defaults и env. Указанный файл обязателен для чтения; неизвестные/повторные поля, неправильные типы, пустой документ и несколько документов отклоняются. Ошибки показывают источник и поле либо строку без исходных значений и DSN.
- Непустой env перекрывает YAML. Пустой не стирает файл. Каталог env заменяет YAML-дополнения целиком; встроенный guru сохраняется, неоднозначные имена обрабатываются по прежнему контракту.
- Четыре таймаута положительные; лимит анализов неотрицательный. Проверка синтаксиса не требует сети или готового mirror. Файл не содержит DSN и не поддерживает includes/подстановку env.
- Compose монтирует выбранный BACKEND_CONFIG_PATH read-only, запрещает создание каталога при отсутствии файла и не перебивает файл стандартными значениями env. Явный SOURCE_URL имеет приоритет над GENTOO_REPOSITORY_URL.

## Risks / Trade-offs

- Env из существующего контейнера может перекрывать изменённый файл → описать приоритет и пересоздание после изменения env.
- URL backend задаёт provenance, не источник sync → изменение источника согласовывается оператором в обоих сервисах.
- Worker timeout прекращает ожидание HTTP, не гарантирует остановку генерации → сохранить эту границу в документации.

## Migration Plan

Сначала пересобрать и пересоздать backend. Затем изменения того же YAML применять через restart; смену env или bind source — через recreate. API и БД не мигрируют, frontend и Gentoo runtime не пересобираются. Рабочие контейнеры в ходе реализации не меняются.
