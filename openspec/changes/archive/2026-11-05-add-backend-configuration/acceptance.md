# Проверка конфигурации backend

Это архивный отчёт: команды и условия относятся к моменту проверки. Актуальные команды запуска и обновления приведены в [руководстве Compose](../../../../docs/local-compose.md).

Проверено локально 2026-11-05. Рабочие контейнеры, PostgreSQL и volumes не изменялись. Существующие изменения очереди и API v1 сохранены; commit и push не выполнялись.

## Подтверждённое поведение

Backend загружает defaults, YAML из --config и непустые env. Пустые env сохраняют YAML; 0 действует как отключение предела анализов. Без файла используется standalone-конфигурация. Чтение env из подготовки отдельных анализов удалено: фабрика получает URL, профиль и HTTP-клиент явно.

Тестами проверены:

- defaults, частичный файл, env overrides всех групп, пустые env, явный ноль и отключение worker/overlays через YAML;
- отсутствие автоматической интерполяции env и сохранение относительных путей;
- недоступный файл, каталог вместо файла, пустой/неверный документ, несколько документов, неизвестные и повторные поля;
- строгие типы без преобразования чисел/boolean в строки, дробные/отрицательные лимиты, переполнение, длительности без единиц и неположительные таймауты;
- отсутствие значений конфигурации в диагностике, DSN только из env, ошибочная конфигурация до подключения к БД;
- замена YAML-каталога env-каталогом, сохранение встроенного guru и неоднозначности повторного имени, ошибки masters и доверенных URL;
- отсутствие обращений к overlay storage при проверке, загрузка штатного файла Compose;
- реальное ожидание HTTP-ответа worker с настроенным timeout и сохранение настроек фабрики после изменения process env;
- прежние сценарии API v1, очереди, закрепления ревизий, восстановления и overlays.

Добавлена прямая зависимость go.yaml.in/yaml/v3 v3.0.6, go.mod/go.sum приведены в порядок через go mod tidy. Доменные модели, схема БД, протокол worker и frontend в рамках этого изменения не менялись.

## Выполненные проверки

Из backend/ прошли:

```sh
go test -count=1 ./...
go test -race -count=1 ./internal/backendconfig ./cmd/gentoo-update-intelligence-server ./internal/analysishttp
go vet ./...
go build -o /tmp/guit-config-server ./cmd/gentoo-update-intelligence-server
```

Новые и изменённые Go-файлы обработаны gofmt. Timeout проверялся на управляемом HTTP-сервере loopback, без обращения к рабочему worker.

Рендер `docker compose --env-file /dev/null -f compose.yaml config --format json` проверен с синтетическим POSTGRES_PASSWORD. Подтверждены read-only mount, create_host_path false, --config и отсутствие принудительного env-default лимита 1. Отдельные сценарии проверили limit 0, worker timeout 3m, общий GENTOO_REPOSITORY_URL и приоритет явного SOURCE_URL. Настройка worker generation limit остаётся 2.

Проверены итоговый diff, whitespace tracked и новых файлов, строгая валидация OpenSpec. Выполнен review обработки ошибок и секретов; precision-проход humanize-docs сохранил команды, приоритеты, условия и границы настроек.

## Применение и ограничения

Первое обновление требует пересборки и пересоздания backend:

```sh
docker compose --env-file /dev/null up -d --no-deps --build backend
```

При уже запущенных зависимостях и действующем POSTGRES_PASSWORD из текущего терминала команда подключит файл config/backend.yaml. Затем изменение того же файла применяется через restart backend, а изменение env или BACKEND_CONFIG_PATH — через recreate. Непустые env существующего контейнера продолжают перекрывать YAML.

Полный запуск контейнера с новым bind mount, изменение файла с последующим restart и пользовательский сценарий на рабочем стеке здесь не выполнялись; их повторяет пользователь. Проверка create_host_path выполнена по рендеру Compose, а не попыткой запуска с отсутствующим файлом.

Миграция БД и пересборка Gentoo runtime не нужны. Для одного изменения конфигурации frontend не требуется; если прежний переход на API v1 ещё не применён, backend/frontend обновляются вместе по руководству API. Worker timeout ограничивает ожидание HTTP, а не гарантирует остановку генерации. URL источника backend нужно согласовывать с отдельным sync-сервисом.

## Последующая ручная приёмка

После автоматических проверок пользователь обновил локальный стек. По журналу PostgreSQL подтверждено несовпадение нового тестового пароля с паролем существующей роли guit; backend завершался из-за отказа аутентификации, а nginx — из-за отсутствующего upstream backend. После согласования пароля пользователь подтвердил работающий стек. Обычные команды Compose теперь читают локальный `.env`, исключённый из Git; обёртка dev-compose удалена. Актуальные команды находятся в руководстве Compose.

Пользователь подтвердил открытие прежнего отчёта и создание нового анализа. Затем временно изменил analysis.concurrency_limit с 1 на 2, выполнил restart backend без пересборки и подтвердил успешный новый анализ. Это проверка запуска с изменённым YAML, не измерение фактического числа одновременных анализов; пределы 1/2/0 проверены автоматическими тестами.

После приёмки значение в config/backend.yaml возвращено на согласованное штатное 1. Пользователь выполнил restart backend и подтвердил работоспособность после возврата. Лимит генераций worker остаётся 2. Локальная ручная приёмка завершена; полный Playwright suite и нагрузочная приёмка в этом прогоне не выполнялись.
