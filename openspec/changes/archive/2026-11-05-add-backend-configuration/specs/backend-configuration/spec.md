## Purpose

Управлять существующими настройками backend и четырьмя таймаутами через YAML и env без пересборки образа при изменении файла.

## ADDED Requirements

### Requirement: Источники настроек
Backend SHALL загружать defaults, необязательный YAML из `--config <path>`, затем непустые существующие env. Пустая env SHALL NOT стирать YAML; строка `0` SHALL считаться значением. Без --config SHALL сохраняться запуск через env и defaults. Автоматический поиск файлов, includes и интерполяция env в YAML SHALL NOT выполняться.

#### Scenario: Приоритет
- **WHEN** значение задано в YAML и непустом env
- **THEN** действует env, а пустой env сохраняет значение YAML

#### Scenario: Без файла
- **WHEN** --config не указан
- **THEN** backend использует defaults и env, не читая файлы конфигурации автоматически

### Requirement: Строгий YAML и ранняя проверка
Backend SHALL отклонять недоступный указанный файл, пустой документ, неверный корневой тип, неизвестные/повторные ключи, неправильные типы и несколько документов. Итоговые настройки SHALL проверяться до БД и очереди без проверки сетевой доступности и готовности mirror. Диагностика SHALL показывать источник и поле либо строку, не выводя YAML целиком, DSN или секретные значения.

#### Scenario: Ошибочный файл
- **WHEN** явно указанный YAML содержит ошибку
- **THEN** запуск завершается до подключения к БД, без fallback на env-only

### Requirement: Параметры backend
Конфигурация SHALL охватывать HTTP address, read_header_timeout, idle_timeout, startup_timeout, лимит анализов, repository name/source_url/path/commit, overlays path/catalog, metadata worker_url/profile/worker_timeout. Таймауты SHALL быть положительными длительностями, лимит — неотрицательным целым. DSN SHALL задаваться только существующим DATABASE_URL env.

#### Scenario: Таймауты и лимит
- **WHEN** оператор задаёт положительную длительность и лимит 0
- **THEN** таймаут применяется, а предел анализов отключается; неположительная длительность и дробный/отрицательный лимит отклоняются

### Requirement: Каталог и параметры worker
YAML catalog SHALL дополнять встроенный guru; непустой env-каталог SHALL заменять YAML-дополнения целиком. Прежняя семантика masters и неоднозначных имён SHALL сохраняться. Backend SHALL передавать загруженные URL, профиль и настроенный HTTP-клиент явно, без чтения env внутри анализа.

#### Scenario: Подготовка metadata
- **WHEN** анализ обращается к worker
- **THEN** используются настройки текущего запуска и HTTP timeout, а последующее изменение env не меняет уже загруженную конфигурацию
