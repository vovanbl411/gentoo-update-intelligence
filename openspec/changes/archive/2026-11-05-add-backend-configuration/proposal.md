# Proposal

## Why

Настройки backend читаются из env в нескольких местах, а таймауты зашиты в коде. Оператору нужен YAML-файл для изменения обычных параметров без пересборки образа.

## What Changes

- Единая типизированная конфигурация: defaults → YAML → непустые env; строка `0` остаётся действующим значением.
- Необязательный `--config <path>`, строгий YAML и проверка итоговых настроек до БД и очереди.
- Существующие параметры backend и четыре положительных таймаута; DSN только в env.
- Read-only файл в Compose без принудительных env-defaults; сохранение общего URL Gentoo override.
- Явная передача worker URL, профиля и HTTP-клиента вместо чтения env при каждом анализе.

## Capabilities

### New Capabilities

- `backend-configuration`: источники, схема, валидация и применение настроек backend. Спецификация становится основным источником требований этой новой области; остальные контракты не переносятся.

### Modified Capabilities

- `local-compose`: подключение YAML, env overrides и применение через restart/recreate.

## Impact

Запуск backend, provider factories, зависимости Go, Compose и документация. API v1, формат хранения, очередь, CLI, протокол и конфигурация worker не меняются. Новые механизмы отмены, пул БД и логирование не добавляются. Проверки: конфигурационные сценарии, HTTP timeout, регрессия backend, рендер Compose. Рабочий стек обновляет пользователь.
