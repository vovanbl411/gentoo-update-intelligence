# Proposal

## Why

Пользователь согласовал проверку Gentoo musl-hardened + GNU как базы worker/sync. Нужно подтвердить профиль, свойства собранных ELF-файлов и совместимость metadata, не выдавая название профиля за доказательство общей безопасности.

## What Changes

- Использовать официальный закреплённый amd64-манифест musl-hardened stage3 с прежним snapshot и GNU-инструментами.
- Сначала собрать отдельные candidate-теги; сохранить текущую musl-базу для сравнения и отката.
- Проверить свойства ключевых ELF-программ, размер, инструменты, HTTPS и metadata на прежнем профиле анализа.
- После успешной приёмки перевести стандартную сборку и документацию на проверенную базу.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

Нет: контракты анализа, API, сети и volumes сохраняются. Для изменения сборки используется `skip_specs: true`.

## Impact

Gentoo Dockerfile.base, проверка ELF и документация сборки/приёмки. Профиль анализа пакетов не меняется. BusyBox и systemd не добавляются как управляющие процессы. Существующие рабочие контейнеры/volumes не пересоздаются; публикация, commit и push вне задачи.
