# Design

## Context

API v1 сохраняет полный результат и преобразует прежний формат хранения в DTO. Удаление полей существующего endpoint нарушило бы контракт.

## Goals / Non-Goals

**Goals:** компактный ответ и читаемый отчёт с сохранением оснований и ограничений.

**Non-Goals:** изменение Analyzer, схемы хранения и формата полного API.

## Decisions

- Новый GET `/api/v1/analyses/{id}/report` использует тот же источник задания и ошибки, но отдельный DTO. В отличие от изменения существующего ответа это сохраняет совместимость клиентов.
- Компактный DTO исключает содержимое snapshots, provenance и повторяющиеся диагностики; полный ответ остаётся доступен по запросу. Это сокращает сетевой ответ, но не чтение из БД.
- Frontend вычисляет сводку и фильтры по возвращённым фактам и раскрывает детали пакета по требованию. Новые правила оценки риска не вводятся.

## Risks / Trade-offs

- Потеря основания при сокращении ответа → проверить соответствие findings, evidence, diff и ограничений полному DTO.
- Большие планы создают нагрузку на браузер → показывать список порциями и создавать детали при раскрытии.

## Migration Plan

Сначала развернуть backend с новым маршрутом, затем frontend. Откат frontend возможен на прежнюю версию с полным endpoint; данные и миграция БД не меняются.
