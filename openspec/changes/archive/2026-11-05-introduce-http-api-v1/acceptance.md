# Проверка HTTP API v1

Проверено локально 2026-11-05. Рабочие контейнеры, PostgreSQL и volumes не изменялись. Изменения очереди из предыдущего этапа сохранены. Commit и push не выполнялись.

## Проверенный контракт

POST и GET используют `/api/v1/analyses`, Location указывает на версионированный GET. Прежние API-маршруты возвращают JSON 404 и не создают задания. Неподдерживаемые методы известных endpoints возвращают JSON 405 с Allow. Ошибки имеют code/message, envelope — явные result/error, включая null.

Backend-тесты подтвердили:

- преобразование прежнего JSON из обеих таблиц хранения без Provider, повторного анализа или изменения результата;
- совпадение с полным fixture v1, snake_case, нормализацию коллекций и сохранение nullable значений;
- пять видов evidence, нулевые индексы, известную пустую строку и отсутствующее значение;
- сохранность точного metadata content, SHA-256 и полного provenance генерации, включая masters, make.conf и параметры egencache;
- частичные сравнения, ограничения и ошибки отдельных Lookup;
- новый POST с пользовательским контекстом, сохранение прежнего JSON результата и выдачу DTO v1;
- регрессию очереди, восстановления и ограничений параллельности через новые маршруты.

Канонический прежний fixture сохранён в backend testdata. Fixture v1 используется для сравнения контракта и отдельной проверки frontend.

## Выполненные проверки

Из `backend/` прошли:

```sh
go test -count=1 ./...
go test -race -count=1 ./internal/analysishttp ./cmd/gentoo-update-intelligence-server
go vet ./...
go build -o /tmp/guit-api-v1-server ./cmd/gentoo-update-intelligence-server
```

После финального review обработчика повторно прошли целевые тесты и vet HTTP-пакета, затем сборка backend. Новые и изменённые Go-файлы обработаны gofmt.

Из `frontend/` прошли:

```sh
npm run typecheck
npm test
npm run build
npm run test:proxy
```

13 unit-тестов проверяют модель v1, состояния, дополнительные поля, некорректные ответы, evidence и общий API-модуль. Проверено сохранение сообщения неизвестного кода ошибки как текста.

`test:proxy` выполнил реальные HTTP-запросы через Vite к временному backend на loopback: полный путь, 202, Content-Type, Location, GET, JSON 404 прежнего и неизвестного API, SPA-страница по UUID. Для nginx проверена конфигурация сохранения URI; сам nginx не запускался.

Playwright `--list` успешно обнаружил 31 сценарий. Браузеры и live-тест не запускались. Дополнительный отдельный tsc-прогон browser-сценариев сообщил об отсутствии типов Node для node:fs/process; зависимости ради этой дополнительной проверки не менялись. Штатный typecheck включает src и unit tests и прошёл.

Проверены итоговый diff, whitespace tracked и новых файлов, OpenSpec --strict. Пройден review по security-review и ai-regression-testing; финальный precision-проход humanize-docs сохранил литералы, порядок действий и ограничения.

## Применение пользователем

При запущенных зависимостях, из корня проекта в терминале с действующим POSTGRES_PASSWORD:

```sh
docker compose --env-file /dev/null up -d --no-deps --build backend frontend
```

После обновления открыть прежний `/analyses/{uuid}`, отправить новый план, проверить progress, completed и повторное открытие отчёта после перезапуска backend. Проверить, что прежний `/api/analyses` и неизвестный `/api/v2/analyses` возвращают JSON 404. Полная браузерная приёмка остаётся отдельным шагом вместе с пользователем.

Миграция БД и пересборка Gentoo runtime не нужны. Backend и frontend нужно обновлять вместе; при откате прежний формат результатов в базе сохраняет совместимость со старой парой компонентов.
