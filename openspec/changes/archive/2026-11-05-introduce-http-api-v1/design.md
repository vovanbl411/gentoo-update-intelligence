# Design

## Context

API хранит JSON с именами Go-полей, включая пять вариантов analyzer.Evidence. В Go Evidence — интерфейс, поэтому для чтения сохранённых findings нужен отдельный DTO хранения с json.RawMessage. Мотивация и границы переноса требований описаны в proposal.md.

## Decisions

- HTTP-слой содержит самостоятельные типы DTO и типизированное преобразование из прежнего JSON хранения. Нет рекурсивного переименования произвольных ключей, runtime reflection или изменений доменных JSON-тегов.
- Новые задания продолжают сохранять прежний resultView. Только ответ GET преобразуется в v1. Старые записи analyses получают completed envelope и тот же адаптер; GET не вызывает Provider и не пишет в базу.
- Все варианты evidence декодируются по RuleID. Отсутствующее evidence остаётся null. Некорректный или неподдерживаемый сохранённый результат даёт INVALID_STORED_RESULT.
- Публичный результат сохраняет вложенность, значения, порядок и полный provenance. Необязательные указатели сохраняют null, известную пустую строку и индекс 0. Отсутствующие коллекции нормализуются без изменения смысла диагностик.
- Ошибки HTTP имеют стабильные коды. Причина failed задания оборачивается в ANALYSIS_FAILED, Err отдельного Lookup — в METADATA_LOOKUP_FAILED. Сообщения остаются текстом.
- Nginx и Vite передают /api без rewrite. API namespace никогда не подменяется SPA HTML. Frontend использует общий API-модуль и новую схему; визуальное оформление не меняется.

## Risks / Trade-offs

- Прямой переход ломает старые API-клиенты → backend и frontend развёртываются вместе; прежние маршруты явно проверяются как недоступные.
- Ошибка адаптера может потерять evidence или provenance → fixtures обоих форматов хранения, всех правил и nullable значений, сравнение содержимого metadata и SHA-256.
- Незакоммиченная очередь из предыдущего этапа → сохранить её поведение и повторить тесты очереди с маршрутами v1.

## Migration Plan

Миграции БД нет. Пользователь пересобирает и пересоздаёт backend и frontend вместе, открывает прежний UUID и создаёт новое задание. Gentoo runtime не пересобирается. При откате к прежней паре backend/frontend формат результатов в базе остаётся совместимым.
