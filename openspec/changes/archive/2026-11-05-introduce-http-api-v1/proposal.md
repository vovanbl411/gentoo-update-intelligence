# Proposal

## Why

HTTP API сейчас сериализует внутренние Go-структуры и использует неверсионированные адреса. Перед дальнейшим развитием frontend нужен самостоятельный публичный контракт с устойчивыми именами полей и ошибками.

## What Changes

- **BREAKING**: только POST `/api/v1/analyses` и GET `/api/v1/analyses/{id}` вместо прежних API-адресов.
- Полные явные DTO с `snake_case`, списками `[]`, словарями `{}` и отсутствующими значениями `null`.
- Структурированные ошибки с кодом и сообщением на уровне HTTP, задания и Lookup.
- Чтение прежних результатов через адаптер без повторного анализа и изменения формата хранения.
- Frontend, nginx, Vite, тесты и документация переходят на v1; страницы `/analyses/{id}` сохраняются.

## Capabilities

### New Capabilities

- `http-api`: публичный транспортный контракт v1. Он становится основным источником требований к HTTP DTO, адресам, ошибкам и совместимости; docs/http-api.md сохраняет пояснения, примеры, хранение и восстановление.

### Modified Capabilities

- `analysis-frontend`: работа с DTO v1 и структурированными ошибками.
- `local-compose`: сохранение полного API-пути при proxy и новый Location.

## Impact

HTTP-слой, frontend и proxy; доменные модели, CLI, worker protocol, схема PostgreSQL и результаты в базе не меняются. Конфигурационный файл, стилизация, авторизация и новые правила анализа не входят в задачу. Приёмка включает контрактные fixtures, оба формата сохранённых анализов, регрессию очереди, Go/frontend checks и проверки proxy. Рабочий стек обновляет пользователь.
