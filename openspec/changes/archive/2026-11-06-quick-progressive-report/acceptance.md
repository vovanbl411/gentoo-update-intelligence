# Приёмка

## Вход и изоляция

Вход: `testdata/parser/ebuild-updates-2.txt`. Для сравнения закреплены `gentoo` `b3c5634f01d86a33bc5fc0a599f5c318989a2839`, `gentoo-zh` `53e6cacef79d87f347219314b357be7d2714526a`, `umbriel-overlay` `7b73f8dfac5f5896b088def7e1670e7073437947`. Зеркала overlays загружены с разрешения пользователя в `/tmp`; тестовый Compose использует отдельные volumes базы и cache, а локальный Gentoo volume подключён только для чтения. Сеть стенда изолирована; после неуспешной попытки обновления используются опубликованные локальные commits.

Перед холодным запуском изменённой версии идентификаторы запущенных backend, worker и frontend совпали с идентификаторами собранных тестовых образов: `14345cf7d925`, `30f24f51f5ec`, `0f8d89c7806a` соответственно. После замера первого отчёта добавлена текстовая оговорка о подготовке более 30 секунд; её проверка проводится на обновлённом frontend при повторном запуске.

«Холодный cache» в этом замере означает пустой generated metadata cache, а не очищенный page cache операционной системы. Существующие пользовательские volumes не очищались.

`docker stats` собирается для backend, worker и PostgreSQL; в повторном запуске изменённой версии также собираются данные frontend. Память приведена по показателю Docker, а не как пиковый RSS всей машины. Потребление Chrome в этих выборках не учитывается.

Первый пробный базовый прогон недействителен: backend не мог изменить права корневых каталогов тестовых mirrors overlays. На 396-й секунде он обработал 57 из 80 запросов; замер остановлен, после чего владельцы двух тестовых каталогов исправлены и для нового прогона созданы отдельные пустые volumes. Результаты пробного прогона не используются для сравнения.

## Результаты

Базовый холодный запуск завершился за 619,3 с; первый отчёт старой версии появился только при завершении. Worker выполнил 30 960 Git-команд, включая 86 `clone` и 86 `checkout`, и 80 запусков `egencache`. По 118 выборкам `docker stats` пик worker составил 279,11% CPU и 765 MiB памяти; последний счётчик block I/O worker — 1,83 MB чтения и 6,2 GB записи. Это выборочные, а не непрерывные пики; block I/O — счётчик контейнера. Исходные выборки сохранены в [`measurements/baseline-cold.json`](measurements/baseline-cold.json).

В холодном запуске базовый resolver проверил 1 570 состояний first-parent для `dev-libs/libei-1.6.0`. Отдельный read-only `git log --first-parent --full-history -1` для того же пути и закреплённого commit вернул родителя `88a930a93edbc5b6e21fbf80748e649281dae402` за 0,082 с; ранее сохранённая приёмка указывает ту же историческую ревизию. Этот отдельный запрос не заменяет сравнение итоговых отчётов.

На синтетической истории с 80 промежуточными commits `BenchmarkDeletedEbuildHistory` при `-benchtime=3x` показал 526 мс на последовательный обход и 20 мс на path-limited поиск. Результаты проверены на Intel Core i7-1260P; benchmark не измеряет генерацию metadata.

Повторный базовый запуск с заполненным cache завершился за 550,8 с. Worker выполнил 30 462 Git-команды, включая 86 `clone` и 86 `checkout`; `egencache` не запускался. По 107 выборкам пик worker составил 210,27% CPU и 767,7 MiB памяти; его счётчик block I/O вырос примерно с 3,15 MB / 6,22 GB до 31,2 MB / 11,9 GB. Исходные выборки сохранены в [`measurements/baseline-warm.json`](measurements/baseline-warm.json).

В холодном запуске изменённой версии первый промежуточный отчёт появился через API за 0,15 с и в Chrome за 0,96 с; ожидающие metadata были видимы как подготавливаемые. Время Chrome измерено от начала POST при открытии принятого UUID на отдельном frontend. Полная обработка завершилась за 569,6 с. Worker выполнил 1 586 Git-команд, 86 `clone`, 86 `checkout` и 80 запусков `egencache`. По 106 выборкам пик worker составил 279,41% CPU и 759,6 MiB памяти; последний счётчик block I/O — 0 B чтения и 6,01 GB записи. Исходные выборки сохранены в [`measurements/updated-cold.json`](measurements/updated-cold.json).

Во время обработки при прогрессе `8/80` промежуточный ответ содержал 41 запись, пять готовых отчётов с индексами `0, 1, 2, 3, 37` и 36 ожидающих записей. Индексы готовых отчётов сохранили порядок плана.

Итоговые Parser, Analyzer, закреплённые репозитории и все 41 отчёт совпали с базовым холодным запуском, включая snapshots, diff и устойчивые поля provenance. При сравнении исключены временные пути, аргументы и журналы `egencache`, конфигурации с временными путями и переменная `PATH`; эти технические поля зависят от конкретного запуска.

Повторный запуск изменённой версии показал первый отчёт через API за 0,10 с, в Chrome — за 0,85 с; завершение обнаружено через 20,0 с. Worker выполнил 916 Git-команд без `clone`, `checkout` и `egencache`. По пяти выборкам пик worker составил 203,16% CPU и 50,6 MiB памяти; счётчик block I/O изменился с `0 B / 6,01 GB` до `16,4 kB / 6,01 GB`. Исходные выборки сохранены в [`measurements/updated-warm.json`](measurements/updated-warm.json). Backend, worker и пересозданный frontend перед замером использовали собранные образы `14345cf7d925`, `30f24f51f5ec` и `3f20743891b3`.

Повторные результаты обеих версий и холодный результат изменённой версии совпали с базовым холодным результатом по тем же полям и с теми же исключениями временных технических данных.

При отдельной проверке backend перезапущен при прогрессе `2/80`: готовые индексы `0` и `37` оставались доступны после рестарта, все три закреплённые ревизии сохранились, задание завершилось под прежним UUID. Его итог совпал с базовым результатом по тем же полям. Основной Playwright suite прошёл 36 тестов; live-сценарий запущен отдельно на тестовом Compose и также прошёл, включая повторное открытие и загрузку технических данных.

Два одновременно отправленных одинаковых плана проверены при лимите одного активного анализа: второе задание наблюдалось в очереди, оба завершились с совпадающими результатами по указанным выше полям.
