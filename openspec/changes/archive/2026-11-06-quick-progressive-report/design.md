# Design

## Context

Существующий `result` доступен только после завершения задания, а очередные обновления прогресса его очищают. Формат v1 и старые сохранённые результаты должны оставаться совместимыми.

## Goals / Non-Goals

Обеспечить раннее сохранение результатов Parser и Analyzer и постепенное появление готовых сравнений. Распределённый backend и изменение семантики существующих статусов не входят в задачу.

## Decisions

Промежуточный результат хранится отдельно от итогового и читается отдельным маршрутом. Ожидающие записи обозначаются явными индексами; готовые отчёты сохраняют исходный порядок. После рестарта ранее сохранённый промежуточный результат доступен во время повторной обработки закреплённых ревизий. Дедупликация и общий предел подготовки сохраняются. При невозможности доказать канонический профиль по Git worker использует checkout.

## Risks / Trade-offs

Частая запись крупных отчётов увеличивает нагрузку на PostgreSQL → измерить объём операций и при необходимости ограничить частоту публикации. Повторная обработка после рестарта может занять время → сохранять доступный промежуточный отчёт и закреплённые ревизии.

## Migration Plan

Добавить совместимое поле хранения миграцией; старые результаты читать как завершённые. Сначала обновить backend, затем frontend, который обращается к новому маршруту. При откате сначала вернуть прежний frontend, затем backend; прежний backend игнорирует новое поле.
