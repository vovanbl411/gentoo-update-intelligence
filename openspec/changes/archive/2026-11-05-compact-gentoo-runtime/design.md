# Design

## Context

Мотивация и scope описаны в proposal.md. Worker выполняет egencache в отдельных checkout с собственной конфигурацией Portage. Дерево `/metadata/gentoo.git` поставляется через volume и не относится к дереву установки пакетов внутри образа.

## Goals / Non-Goals

Сократить runtime и сделать независимую Gentoo-базу для локальной сборки. Сохранить текущие роли, непривилегированный worker и генерацию metadata без внешней сети. Полная побайтовая воспроизводимость и гарантированное хранение upstream-архивов не обещаются. Публикация в registry выполняется отдельным поручением.

## Decisions

- Компилятор и дерево установки остаются в builder. В чистую финальную стадию переносятся файлы выбранных установленных пакетов и рекурсивные RDEPEND/PDEPEND с учётом USE. Дополнительно проверяются ELF-зависимости; библиотеки, поставляемые вместе с GCC, копируются без самого компилятора.
- Сохранить базу установленных выбранных пакетов, системные учётные записи, конфигурацию загрузчика библиотек, включая ld.so.conf.d, сертификаты и необходимые сгенерированные symlinks. Не переносить домашние каталоги и GnuPG state builder. Проверять sandbox в настоящем контейнере, где доступны /dev и /proc.
- Snapshot закреплён датой и SHA-256; подпись проверяется ключами из закреплённой stage3. Git собирается без binhost и необязательных функций Perl/Rust/GUI. Обновление исходных значений — явное изменение файлов.
- База имеет отдельный Dockerfile. Основной Dockerfile принимает ссылку на базу; локальный workflow собирает её до runtime. После публикации ссылка может задаваться digest registry.
- В runtime остаются Portage, Python, shell, Git с HTTPS и необходимые системные утилиты. Это специализированное окружение metadata, не полноценная система установки пакетов.

## Risks / Trade-offs

- Ebuild могут обращаться к инструментам вне декларативных зависимостей Portage → приёмка реальной генерации и исторических/overlay запросов; неизвестные потребности остаются явным ограничением.
- Удаление дерева установки может нарушить стандартный профиль emerge → отдельная проверка чтения версии Portage и конфигурации runtime.
- Snapshot или distfiles исчезнут upstream → сборка должна завершиться ошибкой без перехода на latest; долговременное зеркалирование отложено.
- Portage API и состав runtime зависят от версии stage3 → она закреплена; обновления требуют повторных проверок.

## Migration Plan

Собирать и проверять отдельные локальные теги, существующие volumes не изменять. Переключить штатную сборку только после приёмки. Для отката использовать сохранённый прежний образ; публикация пока не нужна.
