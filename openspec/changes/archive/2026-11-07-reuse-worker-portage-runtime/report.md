# Отчёт проверки производительности

## Результат

Этап 1 сохранил результаты обоих планов и заметно сократил warm-повтор, когда все metadata уже есть в generated-cache. Для плана 2 медиана завершения уменьшилась с 35,04 до 3,04 секунды, для плана 3 — с 35,04 до 5,04 секунды. Первый metadata-результат на warm-прогонах появлялся примерно через одну секунду в обоих вариантах.

Cold-прогоны не показали устойчивого выигрыша: три прогона нового worker заняли 1101–1144 секунды для плана 2 и 993–1072 секунды для плана 3. Единственный контрольный cold-прогон каждого плана занял соответственно 1116 и 1064 секунды. При одном контрольном наблюдении на план эти значения не позволяют заключить, что холодный анализ ускорился или замедлился. Повторное определение Portage составляло небольшую часть cold-пути, где основную работу выполняют checkout и генерация.

| План | Вариант | Cold: завершение, медиана (диапазон) | Cold: первый metadata, медиана | Warm: завершение, медиана | Warm: первый metadata, медиана |
| --- | --- | ---: | ---: | ---: | ---: |
| 2 | Новый worker, n=3 | 1134,04 с (1101,03–1144,04) | 30,01 с | 3,04 с (3,03–4,05) | 1,02 с |
| 2 | Контроль, n=1 | 1116,04 с | 29,01 с | 35,04 с | 1,01 с |
| 3 | Новый worker, n=3 | 1017,04 с (993,04–1072,03) | 28,01 с | 5,04 с (5,03–5,04) | 1,01 с |
| 3 | Контроль, n=1 | 1064,04 с | 29,01 с | 35,04 с | 1,01 с |

У нового worker warm-прогоны обслужили 80/80 и 76/76 generated-cache hits; контрольные прогоны показали те же числа. Cold-прогоны выполнили 80 и 76 генераций. Нормализованные SHA-256 полных результатов совпали во всех прогонах каждого плана: plan 2 — `65be48f545dfbc1a48152c358dbe0e092160e5e745a649aec7f6fe8e085ccd57`, plan 3 — `04d36bd301cc908dbd166fa1c9515781eda5a87f107df3da815acaceb3b7ced3`. Сравнение включает порядок, findings, Lookup и provenance после разрешённой нормализации.

Ожидаемая структура плана 2 (41 запись, 80 lookup) и плана 3 (43 записи, 79 lookup, семь after-only пересборок) подтвердилась. Максимальный промежуток между гостевыми наблюдениями составил 1,012 с, хостовыми — 1,001 с. OOM не зарегистрирован. В госте было 1 vCPU и 2 GiB RAM; максимальное измеренное потребление cgroup составило 1,32 GiB. В холодных прогонах медианный объём записи на виртуальный диск составил 62,29 GiB для плана 2 и 58,94 GiB для плана 3. В это значение входят контейнеры и операции всей гостевой системы, а не только metadata worker.

Холодные результаты не содержат событий `COLDTRACE`: обе версии собраны штатно, поэтому разбивка времени по внутренним этапам отсутствует. Счётчики логов подтверждают число генераций и generated-cache hits. Число созданных checkout отдельно не инструментировалось; оптимизация этапа 1 checkout не меняет. Единичность успешного вызова `emerge --version` проверена тестом конкурентного разрешения версии. Контрольный вариант представлен одним cold→warm прогоном для каждого плана, поэтому он служит свежей контрольной парой, а не статистической оценкой разброса.
