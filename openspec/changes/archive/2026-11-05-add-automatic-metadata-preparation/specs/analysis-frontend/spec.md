# Spec Delta

## MODIFIED Requirements

### Requirement: Асинхронное создание и наблюдение за заданием
Интерфейс SHALL переходить на `/analyses/<uuid>` после подтверждения приёма и сохранения анализа с UUID. Во время отправки повторная отправка SHALL быть заблокирована; автоматический повтор POST не выполняется. Страница SHALL показывать состояние и прогресс до завершения и затем загружать результат.

#### Scenario: Успешная отправка
- **WHEN** POST подтверждает приём анализа и возвращает UUID
- **THEN** браузер переходит на `/analyses/<uuid>` и запрашивает состояние через GET

#### Scenario: Повторное нажатие
- **WHEN** POST ещё выполняется и пользователь повторно нажимает кнопку отправки
- **THEN** второй POST не создаётся и состояние отправки видно пользователю

#### Scenario: Ожидание и прогресс
- **WHEN** GET сообщает `pending` или `running`
- **THEN** UI показывает состояние, этап и число обработанных запросов и продолжает GET того же UUID

#### Scenario: Завершение и ошибка задания
- **WHEN** GET сообщает `completed` или `failed`
- **THEN** UI показывает итоговый отчёт или возвращённую API причину сбоя и прекращает опрос

#### Scenario: Refresh задания
- **WHEN** пользователь обновляет `/analyses/<uuid>` до завершения задания
- **THEN** UI снова загружает и опрашивает тот же UUID, не создавая новый POST
