# Проверка очереди анализов

Проверено локально 2026-11-05. Изменения не применялись к рабочему Compose-стеку; рабочие volumes не подключались к тестам.

## Поведение

Тесты HTTP handler подтвердили ответ `202` для ожидающих заданий, режимы лимита `1`, `2` и `0`, сохранение `pending/queued` без обращения к Provider, выбор следующего задания после освобождения места, восстановление закреплённых ревизий и продолжение очереди после некорректного сохранённого запроса или ошибки Provider. Дополнительно проверены повтор временной ошибки чтения базы без нового POST и уведомление, поступившее во время завершения проверки пустой очереди.

Тест настройки проверяет значение по умолчанию `1`, `0`, положительные числа до `10000`, отрицательное и нечисловое значение, дробь и переполнение. Рендер Compose без `.env` подтвердил пары анализы/генерации `1/2`, `0/2`, `8/2`. Схема PostgreSQL не менялась.

## Выполненные проверки

Из `backend/` прошли:

```sh
go test -count=1 ./...
go test -race -count=1 ./internal/analysishttp ./cmd/gentoo-update-intelligence-server
go vet ./...
go build -o /tmp/guit-queue-server ./cmd/gentoo-update-intelligence-server
```

Новые и изменённые Go-файлы обработаны `gofmt`. Интеграционный `TestPostgresQueue` отдельно прошёл с race detector на временной PostgreSQL `17-alpine`. Тест подключается через `ANALYSISSTORE_TEST_DATABASE_URL`, создаёт собственную схему и удаляет её после проверки. Обычный запуск без этой переменной пропускает интеграционный тест.

На PostgreSQL проверены повторное применение миграций, выбор самого старого задания, переход в `running/preparing`, возврат прерванного задания в `pending/queued` с сохранением revisions, сохранность конечного результата и восемь конкурентных попыток выбора двух заданий без повторного получения UUID. Тестовый контейнер остановлен и автоматически удалён; рабочая база не использовалась.

Прошли `git diff --check`, проверка whitespace новых файлов и строгая валидация OpenSpec. Review выполнен по итоговому diff; редакционный проход humanize-docs не потребовал дополнительных изменений.

## Ограничения

Полный пользовательский путь через браузер после этого изменения не повторялся. Рабочий backend нужно пересобрать и пересоздать отдельно. Поддерживается один backend; предел не ограничивает размер очереди в PostgreSQL. При недоступности базы активный слот удерживается до сохранения конечного состояния. Выбранные значения не являются результатом нагрузочного подбора.
