# Proposal

## Why

Сейчас анализ зависит от заранее подготовленного снимка одного репозитория и не готовит отсутствующие metadata. Пользователю нужен отчёт по тексту плана, включая доступные оверлеи и явные причины неполного сравнения.

## What Changes

- Добавить Gentoo-контейнер с первоначальной синхронизацией, последующим обновлением раз в пять часов и постоянным volume; при сбое сохранять последнее успешное состояние.
- Закреплять ревизии для каждого анализа, загружать известные оверлеи по требованию и переиспользовать репозитории и готовые metadata; при необходимости готовить metadata точных версий.
- Изолировать ошибки по пакетам, показывать источники или причины отсутствия сравнения и прогресс обработки.
- **BREAKING**: заменить синхронный контракт создания анализа асинхронным; обновить frontend и HTTP-контракт.
- Проверить реальный план из 10 пакетов с Gentoo и оверлеями с пустого volume и повторным запросом, а также нагрузочный план на 1000+ записей.

## Capabilities

### New Capabilities
- `automatic-metadata-preparation`: синхронизация репозиториев и подготовка metadata для анализа плана.

### Modified Capabilities
- `analysis-frontend`: асинхронное создание анализа и отображение прогресса.

## Impact

Затронуты Compose change `add-local-compose`, backend, HTTP API, хранение анализа, frontend и документация запуска. Существующие контракты `docs/metadata-preparation.md`, `docs/metadata-provider.md`, `docs/http-api.md` и `docs/plan-service.md` остаются источниками своих областей; при реализации их нужно согласовать с новой спецификацией, удалив противоречащие ограничения. Перенос этих областей целиком не предлагается.
