# Design

## Context

Provider закреплённых репозиториев не изменяет своё состояние при Lookup. Существующий интерфейс Provider не обещает конкурентную безопасность, а worker объединяет совпадающие запросы до подготовки.

## Goals / Non-Goals

Ускорить независимые запросы и ограничить нагрузку одного worker. Распределённое планирование и отмена анализа не входят в изменение.

## Decisions

HTTP использует параллельный путь только для Provider, явно поддерживающего конкурентные Lookup. Два исполнителя получают уникальные Query, а вызывающий поток последовательно собирает результаты и публикует прогресс. Отчёты строятся после получения metadata в порядке плана. Существующий последовательный путь CLI и сторонних Provider сохраняется.

Слот подготовки получается после дедупликации и охватывает весь resolver, checkout и генерацию. Лимит генерации остаётся независимым; фактическое число генераций не превышает меньший из двух пределов.

Для профиля, который непосредственно является каталогом в закреплённом Git tree, worker может прочитать generated-cache до checkout. Закреплённые commits masters проверяются, а существующие проверки ключа, содержимого и provenance сохраняются. Для ссылок, абсолютных и других неоднозначных путей используется прежний путь с checkout и разрешением ссылок. Полная приёмка этого изменения ещё не проведена.

## Risks / Trade-offs

Два запроса одного анализа увеличивают одновременную нагрузку → общий предел подготовки по умолчанию равен двум. Параллельное ожидание может изменить порядок завершения запросов → прогресс сериализуется, отчёты строятся в исходном порядке.

## Migration Plan

Пересоздать worker с новым значением по умолчанию. Для отката вернуть прежние backend и worker; формат сохранённых результатов и cache не меняется.
