# Frontend анализа

Frontend позволяет отправить план, следить за анализом и открыть сохранённый отчёт по UUID. Для первого запуска используйте [Docker Compose](../docs/local-compose.md).

Результаты проверки и её ограничения описаны в [acceptance.md](acceptance.md), требования к интерфейсу — в [спецификации frontend](../openspec/specs/analysis-frontend/spec.md).

## Работа с интерфейсом

Вставьте текст в поле «План emerge» и нажмите «Анализировать». Необязательное поле «Локально патченные пакеты» принимает точные имена `category/name`, по одному на строку, без версий. Оно передаёт пользовательский контекст Analyzer; сервис сам не определяет наличие локальных патчей.

После `202 Accepted` интерфейс открывает `/analyses/<uuid>` и опрашивает состояние задания через GET. На странице отображаются этап и прогресс; после завершения — итоговый отчёт или причина ошибки. Обновление страницы продолжает наблюдение за тем же UUID.

В карточке пакета раздел Metadata показывает статус сравнения и исходы Lookup для `before` и `after`. Детали изменений, диагностики связи, ограничения и provenance раскрываются по соответствующим заголовкам. Сообщение об отсутствии различий относится только к перечисленным в `ComparedFields` полям. Вспомогательные разделы `EffectiveConfig` и `Upstream` показывают возвращённый статус и причину. Сравнение не охватывает зависимости и не подтверждает metadata установленной сборки.

Информация о пакетах, findings, основаниях и metadata выводится из API; исходный текст плана при повторном открытии не восстанавливается. Отсутствие metadata не означает отсутствие изменений.

## Разработка

Нужны Node.js версии `^20.19.0 || >=22.12.0`, npm и backend, доступный из Vite. По умолчанию Vite обращается к `http://127.0.0.1:8080`. Штатный Compose не публикует порт backend на хост: одного запущенного стека недостаточно для такого подключения. Настройки отдельного backend приведены в разделе [«Окружение backend»](../docs/local-compose.md#окружение-backend).

Из корня репозитория:

```sh
npm ci --prefix frontend
npm run dev --prefix frontend
```

Откройте адрес, выведенный Vite. Запросы `/api` направляются в backend с удалением префикса. Другой адрес backend задаётся переменной `GENTOO_UPDATE_INTELLIGENCE_API_PROXY_TARGET` перед запуском Vite. Для запуска собранного frontend вместе с backend и PostgreSQL используйте Compose: nginx отдаёт HTML для маршрутов приложения и проксирует `/api`, сохраняя ответы с ошибками.

## Проверки

```sh
npm run typecheck --prefix frontend
npm test --prefix frontend
npm run test:browser --prefix frontend
npm run build --prefix frontend
```

Для browser tests нужен установленный браузер Playwright.

Frontend проверяет структуру envelope и используемых массивов ответа при получении данных; дополнительные поля API допускаются. Fixture `tests/unit/fixtures/api-found.json` получен из сериализации CLI для того же формата результата, с добавленным UUID envelope. Ошибка формы evidence сохраняется в отображаемых деталях, а отсутствующие ссылки обозначаются как недоступные.
