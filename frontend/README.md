# Frontend анализа

Frontend позволяет отправить план, следить за анализом и открыть сохранённый отчёт по UUID. Для первого запуска используйте [Docker Compose](../docs/local-compose.md); команды ниже предназначены для разработки интерфейса.

Frontend принят и проверен в браузере с реальным backend и PostgreSQL. Результаты проверки и её ограничения описаны в [acceptance.md](acceptance.md). OpenSpec change `add-analysis-frontend` архивирован; действует [спецификация frontend](../openspec/specs/analysis-frontend/spec.md).

Для локального запуска нужны Node.js версии `^20.19.0 || >=22.12.0`, npm и запущенный backend, настроенный по разделу [«Настройки» инструкции Compose](../docs/local-compose.md#настройки). Из корня репозитория:

```sh
npm ci --prefix frontend
npm run dev --prefix frontend
```

Откройте адрес, выведенный Vite. Запросы `/api` направляются на `http://127.0.0.1:8080`, при этом префикс удаляется. Другой адрес backend можно задать переменной `GENTOO_UPDATE_INTELLIGENCE_API_PROXY_TARGET`. Для запуска собранного frontend вместе с backend и PostgreSQL используйте [инструкцию Compose](../docs/local-compose.md): nginx отдаёт HTML для маршрутов приложения и проксирует `/api`, сохраняя ответы с ошибками.

После `202 Accepted` интерфейс открывает `/analyses/<uuid>` и опрашивает состояние задания через GET. На странице отображаются этап и прогресс; после завершения — итоговый отчёт или причина ошибки. Обновление страницы продолжает наблюдение за тем же UUID.

Проверки:

```sh
npm run typecheck --prefix frontend
npm test --prefix frontend
npm run test:browser --prefix frontend
npm run build --prefix frontend
```

Для browser tests нужен установленный браузер Playwright. Информация о пакетах, findings, основаниях и metadata выводится из API; исходный текст плана при повторном открытии не восстанавливается. Отсутствие metadata не означает отсутствие изменений.

В карточке пакета раздел Metadata показывает статус сравнения и исходы Lookup для `before` и `after`. Детали изменений, диагностики связи, ограничения и provenance раскрываются по соответствующим заголовкам. Сообщение об отсутствии различий относится только к перечисленным в `ComparedFields` полям. Вспомогательные разделы `EffectiveConfig` и `Upstream` показывают возвращённый статус и причину. Сравнение не охватывает зависимости и не подтверждает metadata установленной сборки.

Frontend проверяет структуру envelope и используемых массивов ответа при получении данных; дополнительные поля API допускаются. Fixture `tests/unit/fixtures/api-found.json` получен из сериализации CLI для того же формата результата, с добавленным UUID envelope. Ошибка формы evidence сохраняется в отображаемых деталях, а отсутствующие ссылки обозначаются как недоступные.
