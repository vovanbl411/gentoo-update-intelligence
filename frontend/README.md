# Frontend анализа

Frontend находится на review. Результаты реальной браузерной проверки и её ограничения описаны в [acceptance.md](acceptance.md).

Для локального запуска нужны Node.js, npm и запущенный backend, настроенный по [контракту HTTP API](../docs/http-api.md). Из корня репозитория:

```sh
npm ci --prefix frontend
npm run dev --prefix frontend
```

Откройте адрес, выведенный Vite. Запросы `/api` направляются на `http://127.0.0.1:8080`, при этом префикс удаляется. Для другого адреса backend измените локальную конфигурацию proxy. Будущий сервер публикации должен отдавать HTML для маршрутов приложения и проксировать `/api`, не подменяя ошибки API HTML-страницей.

Проверки:

```sh
npm run typecheck --prefix frontend
npm test --prefix frontend
npm run test:browser --prefix frontend
npm run build --prefix frontend
```

Для browser tests нужен установленный браузер Playwright. Информация о пакетах, findings, основаниях и metadata выводится из API; исходный текст плана при повторном открытии не восстанавливается. Отсутствие metadata не означает отсутствие изменений.

В карточке пакета раздел Metadata показывает статус сравнения и исходы Lookup для `before` и `after`. Детали изменений, диагностики связи, ограничения и provenance раскрываются по соответствующим заголовкам. Сообщение об отсутствии различий относится только к перечисленным в `ComparedFields` полям. Вспомогательные разделы `EffectiveConfig` и `Upstream` показывают возвращённый статус и причину. Сравнение не охватывает зависимости и не подтверждает metadata установленной сборки.

Frontend проверяет структуру envelope и используемых массивов ответа при получении данных; дополнительные поля API допускаются. Fixture `src/fixtures/api-found.json` получен из сериализации CLI для того же формата результата, с добавленным UUID envelope. Ошибка формы evidence сохраняется в отображаемых деталях, а отсутствующие ссылки обозначаются как недоступные.
