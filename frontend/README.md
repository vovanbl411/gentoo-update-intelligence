# Frontend анализа

Frontend позволяет отправить план, следить за анализом и открыть сохранённый отчёт по UUID. Для первого запуска используйте [Docker Compose](../docs/local-compose.md).

Результаты проверки и её ограничения описаны в [acceptance.md](acceptance.md), требования к интерфейсу — в [спецификации frontend](../openspec/specs/analysis-frontend/spec.md).

Проверки перехода на API v1 и последующая ручная приёмка пользователем записаны в [отчёте изменения](../openspec/changes/archive/2026-11-05-introduce-http-api-v1/acceptance.md). Прежние браузерные прогоны из acceptance.md относятся к старому API; результаты проверки промежуточного отчёта и актуального Playwright suite приведены в [отчёте приёмки](../openspec/changes/archive/2026-11-06-quick-progressive-report/acceptance.md).

## Работа с интерфейсом

Вставьте текст в поле «План emerge» и нажмите «Анализировать». Необязательное поле «Локально патченные пакеты» принимает точные имена `category/name`, по одному на строку, без версий. Оно передаёт пользовательский контекст Analyzer; сервис сам не определяет наличие локальных патчей.

После `POST /api/v1/analyses` и `202 Accepted` интерфейс открывает `/analyses/<uuid>` и опрашивает `GET /api/v1/analyses/<uuid>/partial-report`. Он показывает факты Parser и Analyzer до окончания подготовки metadata, готовые сравнения, ожидающие записи и прогресс. Полная подготовка может занять больше 30 секунд. Обновление страницы продолжает наблюдение за тем же UUID; после завершения показывается итоговый отчёт или причина ошибки.

Сводка показывает число пакетов, замечаний, блокировок и сравнений metadata. Список можно искать по имени и фильтровать; дополнительные записи открываются кнопкой «Показать ещё». Раскройте пакет, чтобы увидеть findings, изменения metadata, ограничения и исходы Lookup для `before` и `after`. Сообщение об отсутствии различий относится только к перечисленным в `compared_fields` полям. IUSE описывает значения по умолчанию в metadata, а не effective USE установленной системы. Сравнение не охватывает зависимости и не подтверждает metadata установленной сборки.

Раздел «Технические данные» по запросу загружает полный ответ API, включая snapshots и provenance; его можно скачать как JSON. Ошибка этой загрузки не скрывает основной отчёт.

Информация о пакетах, findings, основаниях и metadata выводится из API; исходный текст плана при повторном открытии не восстанавливается. Отсутствие metadata не означает отсутствие изменений.

## Разработка

Нужны Node.js версии `^20.19.0 || >=22.12.0`, npm и backend, доступный из Vite. По умолчанию Vite обращается к `http://127.0.0.1:8080`. Штатный Compose не публикует порт backend на хост: одного запущенного стека недостаточно для такого подключения. Настройки отдельного backend приведены в разделе [«Окружение backend»](../docs/local-compose.md#окружение-backend).

Из корня репозитория:

```sh
npm ci --prefix frontend
npm run dev --prefix frontend
```

Откройте адрес, выведенный Vite. Запросы `/api` направляются в backend без удаления префикса. Другой адрес backend задаётся переменной `GENTOO_UPDATE_INTELLIGENCE_API_PROXY_TARGET` перед запуском Vite. Для запуска собранного frontend вместе с backend и PostgreSQL используйте Compose: nginx отдаёт HTML для маршрутов приложения и проксирует `/api`, сохраняя ответы с ошибками.

## Проверки

```sh
npm run typecheck --prefix frontend
npm test --prefix frontend
npm run test:proxy --prefix frontend
npm run test:browser --prefix frontend
npm run build --prefix frontend
```

Для browser tests нужен установленный браузер Playwright; локальная команда с Flatpak Chrome приведена в [AGENTS.md](../AGENTS.md#проверки). `test:proxy` запускает временные HTTP-серверы только на loopback и проверяет настоящий Vite proxy без браузера и рабочего backend; для nginx он проверяет сохранение URI по конфигурации, без запуска контейнера.

Frontend использует явные [типы API v1](src/api-types.ts) и общий [API-модуль](src/api.ts). Имена JSON-полей — snake_case; списки не бывают null, отсутствующие значения представлены null. Проверка ответа контролирует envelope и используемые массивы; дополнительные поля допускаются. Ошибки содержат code и message; неизвестный code не мешает показать message как текст.

Fixture `tests/unit/fixtures/api-found.json` задаёт ответ v1. Прежний JSON сериализации CLI сохранён в backend testdata и проверяется адаптером, который не меняет записи в базе. Отсутствующие ссылки evidence обозначаются как недоступные.
